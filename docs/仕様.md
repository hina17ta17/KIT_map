# 最終的に作るもの

金沢工業大学 **扇が丘キャンパス**の案内サイト。白山キャンパスは対象外。

```
┌─ フェーズ1 ─────────────────────────────────┐
│  地図 ＋ 現在地 ＋ 目的地までの経路案内         │  誰でも使える・ログイン不要
└─────────────────────────────────────────────┘
                    ↓
┌─ フェーズ2 ─────────────────────────────────┐
│  ログイン（大学ドメイン限定）・承認制            │
│  3段階の管理者（Lv1 / Lv2 / Lv3）              │
└─────────────────────────────────────────────┘
                    ↓
┌─ フェーズ3〜5 ──────────────────────────────┐
│  学食メニュー ／ 時間割 ／ 教室予約             │  承認された人だけ閲覧
└─────────────────────────────────────────────┘
```

**経路案内は最後まで誰でも無料で使える。** 大学の情報だけログインを要求する。

# フェーズ1（いま作っているもの）

## 完成の定義

**スマホでサイトを開いて、23号館まで歩いて到着できること。**

## 動きの流れ

```
① サイトを開く         航空写真の上にキャンパスと建物が出る
② 現在地を取得         敷地の中 → 現在地を表示
                      敷地の外 → 「圏外」表示（地図は見られる）
③ 目的地を入力         「23号館」「23 302」「図書館」
④ [スタート]
⑤ 経路が光る線で表示
⑥ 手順が出る           1. 北へ 60m
                      2. 12号館の角を右折して 120m
                      3. 23号館 南口 に到着
                      ─────────────
                      🏢 302 は 3階です
⑦ 到着判定             CPの円に入ると「到着しました」
```

## なぜ自分で作るのか

**Google Directions API は構内の通路も教室も知らない。**

| | Googleマップ | このサイト |
|---|---|---|
| 大学までの道 | ⭕ | — |
| 構内の通路 | ❌ | ⭕ 自前のグラフ |
| 「23号館」で検索 | ❌ | ⭕ |
| 「302は3階」 | ❌ | ⭕ |

Google Maps Platform には**屋内経路探索のAPIが存在しない。** ここが製品の存在理由。

## 経路探索の仕組み

**チェックポイントを節点、その接続を辺とするグラフ。** 接続した区間しか通れない。

```
CP ──── CP ──── CP
 │               │
 CP ──────────── CP
```

- 距離は2点間から自動計算
- 種別で重みを変える（主要×1.0 / 一般×1.2 / 細道×1.6 / 階段×1.5）
  → 距離は変えず探索コストだけ変えるので、遠回りでも大通りを選ぶ
- `enabled: false` の接続は探索から外れる（工事中・夜間閉鎖など）
- A* で最短経路を求める

## 到着判定

屋内測位が無いので、面ではなく**半径付きの点**で判定する。

```
チェックポイント（出入口）に半径12m
      ↓
その円に入ったら「23号館に到着」
```

GPS誤差は屋外でも 5〜15m 出るため、半径を狭くしすぎない。

## 教室の扱い

**部屋には座標を持たせない。** 「どの建物の何階か」だけ持つ。

```
「23 302」で検索
      ↓  rooms.json から B-04（23号館）3階 と判明
23号館の入口まで経路探索
      ↓
案内の最後に「302 は 3階です」と出す
```

# 使う技術（すべて無料・契約ゼロ）

| 用途 | 使うもの | 備考 |
|---|---|---|
| 地図描画 | **MapLibre GL JS** | v6 |
| 地図タイル | **国土地理院タイル** | APIキー不要・出典表示が義務 |
| 経路探索 | **A\***（自前グラフ） | ngraph.path を使う予定 |
| あいまい検索 | **fuse.js** | `23・302` `23-302` `23302` すべて一致 |
| 現在地 | **Geolocation API** | `watchPosition` |
| 方位 | **DeviceOrientationEvent** | iOS は `requestPermission()` が要る |
| データ | **静的 JSON** | フェーズ1は**データベース不要** |
| ホスティング | Vercel | 実機テストに HTTPS が必要 |

**従量課金のAPIが1つも無い。** 使われても費用は増えない。

## 建物データの入手元

**国土地理院 基盤地図情報 基本項目 → 建築物の外周線**（JPGIS(GML)形式）。

- 扇が丘のメッシュ番号は **`543665`**（`543664` は西隣で範囲外）
- ファイル名に `BldA` を含むものが建築物の面。`BldL` は線なので使わない
- 1メッシュ約10万棟・90MB。`lib/fgd.ts` が敷地の外接矩形で先に切り捨てる

ただし**手描きでも作れる**（実際に現在の38件は手描き）。地理院の航空写真はトレース可。

# やらないと決めたこと

| やらないこと | 理由 |
|---|---|
| **屋内の経路案内** | 階をまたぐ経路探索をやめる判断をした。フロア図の入手が不要になった |
| **建物内での現在地追従** | 技術的に不可能。Web に気圧計APIが無く階が分からない |
| **BLEビーコン** | 設置・電池交換の運用が発生する。iOS で Web から使えない |
| **QRコード** | フロアタブが現在階を兼ねる設計にしたため不要 |
| **NFCタグ** | 同上 |
| Google Maps / Mapbox | 従量課金が発生する。屋内経路APIも無い |
| メール送信 | 承認通知を送らない設計にした。ドメイン取得が不要になった |
