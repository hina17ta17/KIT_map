# 案内画面の開発計画

作図ツールで作ったデータを使って、**実際に使う案内画面**を作る。

---

# 1. 何を作るか

## 画面は2つに分ける

| URL | 中身 | 見る人 |
|---|---|---|
| **`/`** | **案内画面**（現在地・検索・経路） | **一般の利用者** |
| `/edit` | 作図ツール（いまの `/`） | 自分だけ |

> いま `/` を開くと作図ツールが出る。公開したときに利用者が
> いきなり作図画面を見ることになるので、入れ替える。

## 案内画面の構成

```
┌────────────────────────────────────────┐
│ 🔍 [23号館 / 302 / 図書館 …        ]   │ ← 検索
├────────────────────────────────────────┤
│                                        │
│              地  図                     │
│         （現在地・経路を表示）           │
│                                        │
│                          [＋][−][現在地]│
├────────────────────────────────────────┤
│ 23号館 まで  徒歩4分・280m              │
│  1  北へ 60m 進む                       │
│  2  12号館の角を右折して 120m            │
│  3  23号館 南口 に到着                   │
│  ───────────────                        │
│  🏢 302 は 3階です                       │
└────────────────────────────────────────┘
```

## 動きの流れ

```
① 開く            航空写真の上に建物40件
② 現在地を取得     敷地の中 → 現在地を表示
                  敷地の外 → 「圏外」表示（地図は見られる）
③ 目的地を検索     「23号館」「23 302」「図書館」
④ [ここへ行く]
⑤ 経路が光る線で表示
⑥ 手順が出る
⑦ 到着判定        CPの円に入ると「到着しました」＋階を表示
```

**案内は建物の入口で終わる。** そこから先は「302 は 3階です」と文字で出すだけ。

# 2. 実装の順番

**上から順に作る。各段階で動くものができる。**

| # | 作るもの | 必要なデータ | できるようになること |
|---|---|---|---|
| 1 | `/` に閲覧用の地図 | 敷地・建物 | 建物が色分けで見られる |
| 2 | 現在地の取得・表示 | なし | 自分の位置と誤差の円が出る |
| 3 | 圏内／圏外の判定 | 敷地 | 「圏外」が出る |
| 4 | 目的地の検索 | 建物・部屋 | 「23号館」で引ける |
| 5 | 経路グラフの構築 | **CP・接続** | — |
| 6 | A\* で最短経路 | 同上 | 経路が計算できる |
| 7 | 光る経路の描画 | 同上 | **見た目が完成する** |
| 8 | 手順の文章化 | 同上 | 「12号館の角を右折」 |
| 9 | 到着判定 | CP | 「到着しました」 |
| 10 | 部屋の階を表示 | 部屋 | 「302 は 3階です」 |

**1〜4 はいまのデータで作れる。** 5以降は経路グラフの分断を直してから。

# 3. 必要なもの

## ✅ すでにある

| | |
|---|---|
| 敷地 | 1件 |
| 場所 | 40件・全件命名済み |
| チェックポイント | 98件（出入口57・通過点40・門1） |
| 接続 | 147本・7.6km |
| 到着判定 | 全40箇所に設定済み |

## ⚠ あと少し

| | 状態 |
|---|---|
| **経路グラフの分断** | **C-28 / C-40 / C-48 / C-49 をつなぐ**（10分） |
| 部屋（教室と階） | 情報は手元にある。入力するだけ。**無くても1〜9は動く** |

## 🟢 実装には不要

| | なぜ |
|---|---|
| GPS精度の実測値 | 既定のしきい値で始め、実機で調整すればよい |
| 大学のフロアマップ | 屋内をやらないため |
| APIキー・データベース | 使わない設計 |
| 大学の許諾 | **公開時に必要。開発は進められる** |

## 📦 追加するライブラリ

```
ngraph.graph   経路グラフの保持
ngraph.path    A* 経路探索
fuse.js        あいまい検索（23・302 / 23-302 / 23302）
```

いずれも無料・APIキー不要。

# 4. 決めておくこと

## ★ 確認したいこと（1つ）

**`/` を案内画面にして、作図ツールを `/edit` に移してよいか。**

移さないと、公開したとき利用者に作図ツールが見えてしまう。

## 既定で進めること（指定が無ければこれで実装）

| 項目 | 既定値 |
|---|---|
| 歩行速度 | 分速 80m |
| 精度 ≤20m | 現在地をはっきり表示 |
| 精度 ≤50m | 誤差の円だけ表示 |
| 精度 >50m | **採用しない**（前の位置を維持） |
| 現在地→最寄りCP | 50m以内。無ければ「近くに経路がありません」 |
| 経路から外れたら | 30m 離れたら再計算 |
| 曲がりの判定 | 30度未満は「直進」に統合 |
| 短区間の統合 | 10m未満は前後にくっつける |
| 目印 | 50m以内の最寄り建物名 |
| 到着判定 | CPの半径内に3秒以上 |
| 経路の候補 | 1本だけ出す |
| 雨ルート・バリアフリー切替 | **出さない**（後で足せる） |
| コンパス（方位） | 使わない |

## やらないこと

```
屋内の経路探索        階をまたぐ探索はしない
建物内での現在地追従   技術的に不可能
音声案内・経路の共有   フェーズ1の範囲外
ログイン              フェーズ2
```

# 5. 検証

## 実装中

```powershell
node scripts/check-data.mjs   # データの整合性
npm run build                 # 型チェック込み
```

## 実機

**現在地は HTTPS でないと動かない。** `localhost` は例外的に動くが、
スマホから試すには Vercel へのデプロイが必要。

```
① Vercel に GitHub でログイン
② map-sakusei を Import → Deploy
③ https://map-sakusei.vercel.app をスマホで開く
④ キャンパスを歩いて精度を確認
```

```
あなた                          私

       ↓                        （データ待ちなし）
書き出して check-data           
       ↓                              ↓
   🎉 が出る          →    実装 5〜9 に入る
       ↓

```
