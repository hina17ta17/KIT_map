# データ構造

すべて `public/data/` に置く静的ファイル。**フェーズ1にデータベースは不要。**
座標系は **EPSG:4326（WGS84 / 経度・緯度の順）**。GeoJSON の標準に従う。

作図ツール（`/`）の状態は `localStorage` の `kitmap.draft.v1` に自動保存される。
**それは下書き。`public/data/` のファイルが正式なデータ。**

| ファイル | 中身 | 状態 |
|---|---|---|
| `campus.geojson` | 敷地の外周（Polygon） | ✅ 1件 |
| `buildings.geojson` | 建物・屋外設備（Polygon） | ✅ 38件 |
| `checkpoints.geojson` | 到着判定・目印（Point） | ⏳ 未入力 |
| `links.geojson` | 経路グラフの辺（LineString） | ⏳ 未入力 |
| `rooms.json` | 部屋の一覧（配列） | ⏳ 未入力 |

---

## campus.geojson

```jsonc
{
  "type": "Feature",
  "geometry": { "type": "Polygon", "coordinates": [[[136.62, 36.53], ...]] },
  "properties": { "name": "キャンパス敷地" }
}
```

用途：**圏内／圏外の判定**（`@turf/boolean-point-in-polygon`）。

---

## buildings.geojson

```jsonc
{
  "type": "Feature",
  "geometry": { "type": "Polygon", "coordinates": [[...]] },
  "properties": {
    "tempId":   "B-01",  // 仮ID。作図順に自動採番。★名称が判明しても変更しない
    "category": "hall",  // 種別。下表
    "code":     "23",    // 号館番号。category が "hall" のときだけ使う
    "name":     "23号館", // 表示名。目的地の検索対象
    "floors":   4,       // 階数。0 = 未確認
    "note":     ""       // メモ
  }
}
```

### category

| 値 | 表示 | 例 | 塗り | 枠線 |
|---|---|---|---|---|
| `hall` | 号館 | 23号館 | 白 `#ffffff` | `#475569` |
| `facility` | 施設 | 図書館 / 体育館 / 食堂 | 淡い緑 `#a7f3d0` | `#059669` |
| `outdoor` | 屋外 | グラウンド / 自転車小屋 | 淡い青 `#bae6fd` | `#0284c7` |
| `other` | その他 | 門 / 未分類 | 灰 `#94a3b8` | `#475569` |

> **`tempId` は一度振ったら変更しない。** チェックポイントの `linkedTo` と
> 部屋の `buildingId` がこれを参照するため、採番し直すと参照が壊れる。

## checkpoints.geojson

```jsonc
{
  "type": "Feature",
  "geometry": { "type": "Point", "coordinates": [136.6294, 36.5316] },
  "properties": {
    "id":       "C-01",
    "kind":     "entrance",   // entrance | gate | waypoint
    "name":     "23号館 南口",
    "linkedTo": "B-04",       // 到着とみなす建物の tempId。空なら判定に使わない
    "radius":   12,           // この距離(m)以内に入ったら到着とみなす
    "note":     ""
  }
}
```

| kind | 表示 | 既定半径 | 用途 | 色 |
|---|---|---|---|---|
| `entrance` | 出入口 | 12m | **建物への到着判定** | `#22c55e` |
| `gate` | 門 | 15m | キャンパスの出入口 | `#0ea5e9` |
| `waypoint` | 通過点 | 20m | 案内の目印 | `#a855f7` |

**チェックポイントは経路グラフの節点でもある。** 曲がり角にも置くこと。
CP間は直線で結ばれるので、角にCPが無いと建物を突き抜ける経路になる。

## links.geojson

**経路グラフの辺。案内はここだけを通る。**

```jsonc
{
  "type": "Feature",
  "geometry": { "type": "LineString", "coordinates": [[...], [...]] },
  "properties": {
    "id":      "L-01",
    "from":    "C-01",   // チェックポイントID
    "to":      "C-02",
    "kind":    "normal", // main | normal | narrow | stairs
    "roofed":  false,    // 屋根があるか
    "enabled": true,     // ★false なら経路探索から除外
    "note":    "",
    "lengthM": 42        // 書き出し時に計算して入れる
  }
}
```

### kind と重み

| kind | 表示 | 重み | 効果 | 色 |
|---|---|---|---|---|
| `main` | 主要通路 | 1.0 | 優先的に選ばれる | `#f59e0b` |
| `normal` | 一般通路 | 1.2 | 既定値 | `#fbbf24` |
| `narrow` | 細道 | 1.6 | 遠回りしてでも避ける | `#fcd34d` |
| `stairs` | 階段 | 1.5 | バリアフリー時は除外できる | `#ef4444` |

**重みは探索コストの倍率。実距離は変えない。** 表示される距離は正しいまま、
「裏道を細かく縫う不自然な経路」が出なくなる。

> **線の形状はチェックポイントの座標から毎回生成する。**
> 作図ツール内部では `links` は座標を持たない配列。CPを動かしても線がずれない。

## rooms.json

**配列。GeoJSON ではない。座標を持たない。**

```jsonc
[
  {
    "id":         "R-001",
    "buildingId": "B-04",   // buildings.geojson の tempId
    "code":       "302",    // 部屋番号
    "name":       "",       // 名称（任意）
    "floor":      3,        // 階。地下は負の数（B1 = -1）。0 = 未確認
    "category":   "class",  // class | lab | office | facility | other
    "hint":       ""        // 「南口から入って正面の階段」など
  }
]
```

用途：案内の最後に **「302 は 3階です」** と出す。経路探索には使わない。

階は部屋番号から自動推定される（`302`→3階 / `1203`→12階 / `B01`→地下1階）。
例外のある大学もあるため、入力側で直せるようにしてある。

# 検証ルール（作図ツールが自動チェックする）

| チェック | 意味 |
|---|---|
| つながっていない端点 | 交差点なのに接続していないと大回りの経路になる |
| 経路グラフの分断 | 2つ以上の塊に分かれていると、その先へ案内できない |
| 到着判定がない場所 | CPが紐づいていない建物は「到着」を出せない |
| 通路が届いていない場所 | 25m以内に通路が無い場所は案内できない |

**「✓ すべてのチェックポイントがひと続きにつながっています」が緑になれば、
どのCPからどのCPへも経路が出せる状態。**
